# BreachBrief

**Don't let your breach response cause a second breach.**

AI-Z track, MAIN Summit Hackathon 2026, team 404 LEGENDS.

BreachBrief helps a data protection officer handle a personal data breach. It takes an incident report and the leaked file, works out which notification regimes apply (GDPR, NIS2, DORA) and their deadlines, and drafts the notifications. A human then decides on the risk level and who to notify.

The leaked data itself never reaches the AI model. Every model call goes through the BRANE firewall, and only after local detection, pseudonymisation and a final leak guard have run.

**Legal basis and policy:** [LEGAL.md](LEGAL.md) (legal research, sources) and
[POLICY_MATRIX.md](POLICY_MATRIX.md) (what happens to each data category, and which test proves it).
**Test evidence:** [TEST_PROTOCOL.md](TEST_PROTOCOL.md) (10 cases) and [test_evidence_run.csv](test_evidence_run.csv)
(live BRANE, T1-T5 + E1-E5), both generated by `python make_protocol.py`.

## Pipeline
```
incident report + leaked file
  -> profiler.py   file profiled locally (only counts + data categories leave)
  -> detectors.py  finds names (known list + local spaCy NER + titles), IBANs, IDs, amounts,
                   health data, injected instructions (every occurrence)
  -> policy.py     ALLOW / PROTECT / LOCAL_ONLY / BLOCK, with pseudonym vault kept locally
  -> agent.py      final leak guard re-scans the exact payload
  -> brane_client  BRANE -> OpenAI; fail closed, no fallback
  -> agent.py      output contract: invalid JSON/keys -> one retry (same sanitised payload) -> fail safely
  -> regimes.py    deterministic legal deadlines (GDPR 72h, NIS2 24h/72h, DORA 4h/24h)
  -> protocol.py   audit/test protocol per run (decisions + exact payload, never raw values)
  -> approval.py   HUMAN approves risk level + notifications -> Markdown package in exports/ (never sent)
```

## Run
```bash
python -m venv .venv && .venv/Scripts/activate   # (source .venv/bin/activate on macOS/Linux)
pip install -r requirements.txt   # includes the spaCy model xx_ent_wiki_sm (one download, then offline)
cp .env.example .env              # BRANE_MODE=mock works offline
python scripts/generate_data.py   # synthetic scenarios (already included)
python run_demo.py payroll_misdirected
python run_demo.py hospital_ransomware
python run_demo.py bank_ict_incident
python run_demo.py payroll_misdirected --down   # BRANE unavailable -> nothing sent
python run_demo.py hospital_ransomware --approve --reviewer "J. Doe (DPO)" --risk high --notify authority,csirt,affected_people
python run_demo.py payroll_misdirected --approve --reviewer "J. Doe (DPO)" --risk unlikely --notify none --reason "..."
pytest -v                          # all tests (security, NER, regimes, leak guard, approval, edge cases, UI)
python make_protocol.py            # runs the 10 protocol cases -> TEST_PROTOCOL.md + TEST_PROTOCOL.json
python check_brane.py              # once you have credentials: 1 harmless test call, prints the raw response
```
Protocols are written to `protocol/`, approved packages to `exports/` (both git-ignored; exports contain real names).

### Live BRANE (Team-13 / policy-v1)
`.env` (never committed) holds `BRANE_MODE=live`, `BRANE_BASE_URL=https://brane.ai-z.io/api/v1`, `BRANE_API_KEY`,
`TEAM_BUILD` and `LOCAL_PREMASK`. Calls go to `POST {base}/chat/completions` with model `auto`.

```bash
python configure_policy.py        # PUT /policy: our 25 category rules + 3 semantic rules, prints the saved summary
python check_brane.py             # GET /policy + /policy/catalog, one harmless chat call, prints all X-Brane-* headers
python make_protocol.py           # TEST_PROTOCOL.md (10 cases) + live evidence test_evidence_run.csv (T1-T5, E1-E5)
```

How BreachBrief reads BRANE's answer:

| BRANE response | BreachBrief status | What happens |
|---|---|---|
| HTTP 200, `X-Brane-Routed-To: cloud` or `local` | `ok` | Drafts shown; the X-Brane-* headers are shown as the "BRANE verdict" and stored in the protocol |
| HTTP 422 (policy refusal) | `refused_by_brane` | No model ran, nothing sent; the UI escalates to the human reviewer with `X-Brane-Refused-By` |
| network error, timeout, 5xx, other 4xx, malformed body | `brane_unavailable` | Fail closed, nothing sent, no fallback |

**`LOCAL_PREMASK`** (sidebar toggle "Local pre-masking"):
- `full` (default): everything in POLICY_MATRIX.md is masked locally, and BRANE is the second line.
- `guard_only`: names, emails, phones and health text are left to BRANE's policy (placeholders / local GPU).
  The following are still handled locally:
  - the leaked file never leaves the machine;
  - deadlines are computed locally;
  - approval is still required;
  - injected instructions, encoded blobs and recipients are removed or pseudonymised;
  - IBAN / ID / amount / DOB values are removed, and the final guard re-checks only those four.

  The run protocol then logs a locally masked copy of the payload.

**Rules and product gaps:** [policy_matrix_submission.csv](policy_matrix_submission.csv) (the `kit/MAIN_Policy_Matrix_Template.csv` format).
False positives we hit and worked around:
- BRANE refused our `[IBAN_REMOVED]`-style markers and a JSON key as PASSWORD, so markers now go out as plain words: `(iban removed)`.
- BRANE refused the label "dates of birth", so the category is now described as "age data".
- BRANE forwarded a base64 attachment inside a long report, so encoded blobs are now removed locally.

## Demo UI (Phase 5)
```bash
streamlit run app.py              # offline in mock mode, live with BRANE_MODE=live; localhost only, no telemetry
```
Always visible: the outcome (sent / refused / nothing sent) and a live countdown to every GDPR / NIS2 / DORA deadline.
Below that, the case is walked through in 7 steps. Each step opens with **what happens here** and **why** (the legal basis),
and has Back / Next buttons:

| Step | What you see |
|---|---|
| 1. Incident | Records exposed, special-category records, regimes, earliest deadline, the leaked file's data categories (profiled locally) |
| 2. Protect locally | The original report with every protected span coloured next to the exact payload sent to BRANE; counts; decision per data category; health details only in a "Reviewer only" expander |
| 3. BRANE check | BRANE's verdict from the X-Brane-* headers (cloud / local GPU / refused), model, detected types, and what each outcome means |
| 4. Review drafts | Suggested risk level, facts to confirm (checklist), both drafts editable (edits are kept across steps) |
| 5. Human decision | Named reviewer, confirmed risk level, which notifications, reason when one is skipped (same rules as `approve()`) |
| 6. Export | **Word** notification package (.docx, marked DRAFT until approved), **Excel** audit workbook (.xlsx: deadlines, decisions, BRANE verdict, payload, approval; no draft texts or health details), Markdown copy |
| 7. Audit trail | This run's protocol JSON and the 10-case test protocol (with a run-now button) |

Sidebar: scenario, *Simulate BRANE down*, *Local pre-masking* (off = `guard_only`), *Demo clock* (countdown starts
at the moment of awareness, so deadlines are not already overdue on demo day), and the BRANE mode badge.

## Tests
The names in the *Tested by* column of [POLICY_MATRIX.md](POLICY_MATRIX.md) map to these files:

| Name in the matrix | File |
|---|---|
| Permitted control case, Protected data, Health stays local, Repeated details, Bypass attempt, Check failure (the 5 AI-Z tests) | `tests/test_security.py` |
| NER tests | `tests/test_ner.py` |
| Leak guard tests | `tests/test_leak_guard.py` |
| Approval tests | `tests/test_approval.py` |
| Regime tests | `tests/test_regimes.py` |
| 10 protocol cases (5 AI-Z + 5 edge cases) | `tests/test_edge_cases.py`, defined in `breachbrief/casebook.py` |
| Output contract, live BRANE client (headers, 422), UI | `tests/test_output_contract.py`, `tests/test_brane_client.py`, `tests/test_app.py` |
| LOCAL_PREMASK modes | `tests/test_premask.py` |
| Live evidence T1-T5 + E1-E5 (needs credentials, not in pytest) | `breachbrief/evidence.py`, run by `make_protocol.py` |

Edge cases on top of the 5 AI-Z tests: **E1** an IBAN split over a line break, with dashes or in lower case;
**E2** a name and email only in an email signature and a quoted reply; **E3** health data in Dutch/German and in an
attachment's file name; **E4** polite or obfuscated instructions, and an instruction planted in a CSV cell;
**E5** an affected person mentioned by first name only (first names come from the leaked file only).
